# Tooling & architecture preferences

- Strongly prefers pure-Go libraries over shelling out to system binaries, accepting feature tradeoffs (no hooks, LFS, submodules) to avoid an external dependency. Confidence: 0.7
- Likes dependencies resolved from the local module cache / offline-friendly builds; verify transitive deps are cached before planning on them. Confidence: 0.55
- Dislikes god interfaces where implementations return "not supported" stubs. Prefers small capability interfaces selected by type assertion, so each backend implements only what it can serve and commands degrade cleanly. Confidence: 0.6
- When a backend's model differs structurally (PR refs vs branch-only), prefers returning a declarative spec describing *how* to perform the operation rather than a hardcoded per-backend code path. Confidence: 0.6
- Values keeping backend-specific quirks in per-backend code and letting a table drive the variation. Confidence: 0.5
- The project/repo name is canonical: the CLI binary, the env var prefix, and the config directory must all match it (e.g. `forgit`, `FORGIT_*`, `~/.config/forgit/`). Don't invent a shortened brand name, and treat the repo's own agent/docs file as the source of truth when the code has drifted from it. Confidence: 0.6
- A rename is not done until it is swept through every surface: identifier constants, env var names, config paths, the cobra `Use:` string, help text, TUI banners, and error messages. Verify with a repo-wide grep for the old token plus a build. Confidence: 0.6
- Verify third-party SDK and library signatures by reading the source in the module cache before writing the call — never guess at API shapes (whether a type is a pointer, whether a function exists, which package a type lives in). Guesses are expected to be caught and corrected immediately. Confidence: 0.55
- Leaves no placeholder code behind: no `var _ = x` import stubs, no no-op helpers standing in for unimplemented work, no unused parameters. Self-audit and rewrite the file right after writing it. Confidence: 0.5
- Project enforces a specific Go toolchain quality gate: run `gofmt -w`, `go build ./...`, `go vet ./...`, `staticcheck ./...`, and `go test ./...` together as a final pass before declaring done. Tooling is wired through `mise.toml`. Treat all five as required; running only `go build` is not enough. Confidence: 0.7
- For library interfaces, the preferred test pattern is compile-time conformance via package-level `var _ InterfaceType = (*ConcreteType)(nil)` blocks. The build IS the assertion — when a forge client stops implementing a capability, the build breaks before any test runs. Runtime tests cover the public git layer; capabilities are checked at compile time only. Confidence: 0.65
- "continue" is a valid one-word prompt meaning "keep going on the current task list" — the agent should resume work, sync the todo list, and proceed end-to-end without re-confirming scope. Don't ask "continue with what?" Confidence: 0.6
